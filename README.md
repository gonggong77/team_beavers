# 🌊 이안류 조난자 긴급 탐지 알림 시스템 - 웹 데모

팀 비버즈 · 웹 배포 파트(Streamlit) 담당: 이현경

**모델 파일이 없어도 지금 바로 실행됩니다.** 가상 탐지기(`FakeDetector`)가 이안류 구역과 사람을
만들어내므로, 관찰 → 경고 → 긴급 전환과 알림 발송까지 전부 검증할 수 있습니다.
모델을 받으면 `models/` 에 넣고 경로만 지정하면 실제 추론으로 바뀝니다.

## 실행

```bash
pip install -r requirements.txt
cp .env.example .env
streamlit run app.py
```

영상이 없으면 데모용 영상이 `data/sample_beach.mp4` 에 들어 있습니다.

UI 없이 확인하려면:

```bash
python -m core.pipeline data/sample_beach.mp4 --skip 10
python -m core.rules          # 위험 등급 판정 로직 자체 점검
```

## 두 개의 화면

**기본 화면: 상시 관제**
큰 화면 하나에 샘플 CCTV(A 구역)를 계속 재생하고, 우측에 상황 정보를 띄운다.
아무것도 업로드하지 않아도 화면이 살아 있다. 0.7초 주기로 갱신된다.

`data/cctv/A.mp4` 를 넣으면 그 영상이 배경으로 쓰이고, 없으면 합성 배경으로 대체된다.
다른 구역으로 바꾸려면 `core/scenario.py` 의 `MAIN_BEACH = "A"` 만 고치면 된다.

**테스트 화면: 업로드 분석**
사이드바의 모델 경로 바로 아래 업로더에 영상을 올리면, 같은 큰 화면 자리에
분석 결과가 대신 재생된다. 좌측 상단 제목을 누르면 상시 관제 화면으로 돌아온다.

**관제 화면 표시 방식 3가지**

| 모드 | 이안류 | 사람 | 언제 |
| --- | --- | --- | --- |
| 시나리오 | 시연용 구성 | 시연용 구성 | 모델 오기 전 |
| 사람만 실제 탐지 | 시연용 구성 | 실제 추론 | 사람 모델만 있을 때 |
| 전체 실제 추론 | 실제 추론 | 실제 추론 | 두 모델 다 있을 때 |

사용자 모드에서는 **가진 모델에 맞춰 자동으로** 고릅니다. 개발자 모드에서 직접 지정할 수 있습니다.
사람 모델이 없는데 "전체 실제 추론"으로 두면 **데모용 가짜 사람이 진짜 이안류 구역에 들어가
실제와 구분되지 않는 긴급 알림이 발생**하므로, 자동 선택은 이 조합을 피합니다.

## 두 가지 화면 모드 (사이드바 맨 위 ⚙️ 설정)

| 모드 | 보이는 것 |
| --- | --- |
| 사용자 모드 (기본) | 영상 업로드, 알림 발송 방식, 결과 화면·갤러리·이벤트 기록 |
| 개발자 모드 | + **모델 설정**(이안류/사람 각각 conf·iou·imgsz), 분석 설정, 판정·발송 기준, 관제 표시 방식, 기록 내려받기/비우기 |

이안류 구역과 원거리 CCTV의 작은 사람은 적정 임계값이 서로 달라서, 두 모델의 conf 를 공유하지
않고 따로 잡습니다. 바꾼 값은 사용자 모드로 전환해도 유지됩니다.

> 시나리오와 하이브리드 모드는 **가상 관측구역**을 시연용으로 구성한 것이다.
> 실제 해수욕장 정보가 아니며, 화면 하단에 그 사실이 표시된다. 발표 시 반드시 밝힐 것.

## 설계 원칙 네 가지

**1. 웹은 `Detector` 프로토콜만 안다.**
`app.py` 는 모델이 YOLO인지 가짜인지 모릅니다. 그래서 모델 개발과 웹 개발이 동시에 굴러갑니다.

**2. 화면과 알림은 같은 객체를 본다.**
`AlertEvent` 하나가 화면 로그 테이블과 FCM 알림 메시지에 동시에 쓰입니다.
"나중에 알림용 데이터를 따로 정리"하는 작업이 아예 생기지 않습니다.

**3. 판정 로직은 UI 밖에 있다.**
`rules.py` 는 Streamlit을 임포트하지 않습니다. 알림 담당자가 UI 없이 단독 테스트할 수 있습니다.

**4. `masks.xy` 와 `boxes.xyxy` 만 쓴다.**
둘 다 원본 프레임 픽셀 좌표로 나옵니다. `masks.data` 는 마스크 해상도 기준이라 크기가 어긋납니다.

## 모델은 두 개다

이안류 탐지 모델(segment)과, CCTV 원거리 시점에서 표류자를 찾는 사람 탐지 모델(detect)을
따로 돌려서 `core/detector.py` 의 `DualDetector` 가 결과를 합친다.
사람이 이안류 구역 폴리곤 안에 있는지는 두 모델 결과를 합친 뒤 `rules.py` 에서 판정한다.

| 모델 | 위치 | env |
| --- | --- | --- |
| 이안류 탐지 (segment) | `models/rip/best.pt` (기존처럼 `models/best.pt` 도 인식) | `RIP_MODEL_PATH` |
| 사람(표류자) 탐지 (detect) | `models/person/best.pt` | `PERSON_MODEL_PATH` |

## 모델을 받았을 때 (딸깍 3단계)

1. 각 모델 가중치를 위 표의 폴더에 배치
2. `.env` 의 `RIP_MODEL_PATH` / `PERSON_MODEL_PATH` 확인
3. `requirements.txt` 의 `ultralytics` 주석 해제 후 모델팀과 동일 버전으로 설치

한쪽 모델만 먼저 받았다면 그 모델만 실제 추론으로 동작하고, 나머지 한쪽은 자동으로
데모용 `FakeDetector` 로 채워진다. 둘 다 없으면 전체가 데모 모드로 동작한다.
클래스 이름이 예상과 다르면 사이드바에서 이안류/사람 클래스를 직접 고르면 됩니다.

## 위험 등급 (FR-03)

| 등급 | 조건 |
| --- | --- |
| 관찰 | 이안류 의심 구역이 없음 |
| 경고 | 의심 구역은 있으나 구역 안에 사람이 없음 |
| 긴급 | 의심 구역 안에 사람이 있음 → 알림 발송 대상 |

사람이 구역 안에 있는지는 바운딩 박스 중심점의 폴리곤 포함 여부로 판정합니다
(`rules.py` 의 `mark_persons_in_rip`, 기준점은 `center` / `bottom` 중 선택 가능).

## 알아둘 제약

- **성능**: CPU 추론이라 전 프레임 처리는 불가능합니다. 사이드바의 프레임 간격을 기본 5로 두었습니다.
  발표용 영상은 10~20초 분량을 권장합니다.
- **배포**: Streamlit Community Cloud에는 GPU가 없습니다. 시연은 로컬을 기본으로 잡으세요.
- **라이선스**: Ultralytics는 AGPL-3.0입니다. 공개 배포 시 소스 공개 의무가 생기므로 발표 자료에 명시하세요.
- **안전 표현**: 모든 출력에 "현장 안전요원 확인 필요" 문구가 붙습니다 (NFR-04). 지우지 마세요.
- **개인정보**: 얼굴 인식이나 신원 식별 기능은 구현하지 않습니다 (NFR-05).
